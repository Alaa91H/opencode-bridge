# تقرير الجرد التشغيلي الآمن — T01

أضيف أمر قراءة فقط لحالة الجهاز عند تشغيله **على الخادم المقصود**. نجاح CI يؤكد صحة الأداة ولا يثبت أنها نفذت على الإنتاج.

```bash
python scripts/host-inventory.py
```

المخرجات JSON تحتوي هوية commit وVERSION من Git، حالة اتساخ الملفات المتتبعة دون أسماء الملفات، وهوية الإصدار المنشور إذا كانت صالحة، حالة ثلاث وحدات systemd محددة فقط، نسخ مكتبات Python الأساسية، سعة القرص والذاكرة، وسياسات تحديث Bridge وUbuntu. تعرض وجود .env وصلاحياتها، ولكنها لا تقرأ محتوياتها مطلقًا.

لا تعرض أسماء ملفات المهام، نصوص جلسات المستخدم، مسارات تشغيل خاصة، مفاتيح GitHub أو Telegram، أسماء مزودي النماذج، قيم متغيرات البيئة، أية أوامر عامة أو سجل journal. تستخدم أوامر git وsystemctl allowlist ذات مهلة تنفيذ قصيرة وتتعامل مع الأعطال بصورة غير مدمرة.

## معيار الإكمال الحقيقي

1. تشغيل الأمر على بيئة staging وخادم الإنتاج بحساب الخدمة ذي الصلاحيات المحدودة.
2. مقارنة هوية Git وملف deployment-identity وإصدار binary الفعلي ونسخ Python المثبتة؛ الأداة لا تتحقق من اتصال Telegram end-to-end.
3. إجراء جرد منفصل لمساحات العمل المعتمدة ومنافذ الشبكة وحدود صلاحيات الوكيل، دون طباعة أسماء مستودعات خاصة أو أسرار.
4. توثيق حالة systemd والنسخ الاحتياطية والتحديثات وفجوة الموارد ببيانات فعلية.

النتيجة `unavailable` أو `invalid` تعني أن الحالة تحتاج تشخيصًا؛ لا تعتبر نجاحًا. لا يتضمن هذا التغيير تشغيلًا تلقائيًا على الخادم.
