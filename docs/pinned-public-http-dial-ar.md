# حماية ربط DNS بالاتصال الفعلي — T02/T17

التنزيلات المباشرة بواسطة httpx لم تعد تعتمد على فحص DNS سابق منفصل فقط. يقوم backend جديد باستعلام أسماء المضيفين في لحظة فتح اتصال TCP، ويرفض جميع الأجوبة إن ظهر فيها عنوان داخلي أو غير عالمي، ثم يتصل بالعنوان الرقمي الموافق نفسه دون إعادة حل اسم المضيف.

يبقى Host header واسم المضيف المستخدم في TLS SNI والتحقق من شهادة HTTPS على الاسم الأصلي، ولا تُعطل شهادات TLS. يرفض النقل استخدام Unix sockets ويفشل بأمان إذا تغيرت الواجهات الداخلية لمكتبات httpx/httpcore المثبتة بإصدارات محددة.

يُطبق هذا الإجراء على DownloadService للتنزيلات المباشرة في الإنتاج فقط. تتجاوز اختبارات الخادم المحلي هذا القيد عبر allow_private_hosts=True، وهي خاصية اختبارية غير مناسبة للإنتاج.

## حدود الحماية

هذا لا يضيف سياسة شبكة خروج على مستوى نظام التشغيل. ما زال تشغيل yt-dlp وأي برنامج خارجي يمكنه إجراء اتصالات مختلفة بعد تحقق URL، وبالتالي يحتاج container/network namespace أو egress firewall تحظر IP الداخلية والخاصة، بالإضافة إلى اختبارات عملية على staging. كما يجب إثبات سلوك DNS rebinding أثناء اتصال HTTPS حقيقي في بيئة اختبار معزولة.

لا تعتبر T02 مكتملة حتى توجد شبكة خروج مقيدة وصلاحيات وكيل تنفيذ محدودة ونتائج اختبارات SSRF حقيقية شاملة.
