## Observability & Troubleshooting

ابدأ بـhealth/readiness في T32، ثم structured logs في T31، traces في T30، metrics في T29. للأعطال المتكررة راجع T41 وOperations Guide. لا تُعالج corruption أو migration failure بتعديل DB يدوي قبل أخذ snapshot موثّق.

## Documentation change policy

كل feature كبيرة يجب أن تضيف/تحدث ملف `docs/tNN-*.md` في commit/series المرحلة نفسها. الروابط أعلاه يجب أن تبقى صالحة، ووثائق release/migration يجب أن تعكس production path الحالي لا legacy path.
