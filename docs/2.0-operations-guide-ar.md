# OpenCode Bridge 2.0 — دليل Architecture & Operations

## Architecture
Telegram adapters رقيقة؛ use-cases في services؛ domain يحوي policies/contracts؛ infrastructure يحوي SQLite/OpenCode/storage/media/metrics/security/deployment. Durable Queue هي task engine الوحيدة وBridgeSettings هو config boundary.

## DB schema
schema_migrations يدير الإصدارات. الجداول الدائمة تشمل tasks/attempts/events/attachments/outputs/schedules/runs/sessions/user_settings/resource snapshots/failure records. WAL/foreign keys/busy timeout/integrity checks مفعلة عبر BridgeDatabase.

## Task state machine
draft → queued → leased → running/waiting/retrying → completed/failed/cancelled/dead_letter. lease/heartbeat/retry/idempotency تمنع فقد العمل والتكرار الفعال.

## Scheduler semantics
once/interval/cron/daily/weekly/monthly/weekdays مع IANA timezone/DST. misfire: skip/run_once/catch_up/coalesce. overlap: forbid/allow/replace/queue. occurrence idempotency يمنع التشغيل المكرر.

## Failure semantics
retryable faults تستخدم bounded backoff؛ non-retryable تصبح failed/dead-letter. committed task لا يحذف عند crash. circuit breakers تعزل Telegram/OpenCode/model/GitHub/storage. cancellation تنظف الموارد وتعيد subprocess reap.

## Attachment pipeline
input → detect → validate → normalize → extract → segment → agent → compose. CAS storage وstreaming chunks؛ archives manifest-first مع traversal/bomb guards؛ intelligence router يختار direct/chunk/transcript/frames/manifest حسب النوع والحجم/context.

## Security profiles
SAFE default ثم DEVELOPMENT/POWER/HOST_ADMIN. HOST_ADMIN allowlist فقط. OpenCode loopback، sandbox للبناء، output jail، secret redaction، systemd hardening وsystemd credentials اختيارية.

## Deployment
releases/<version> + current symlink. verify → test → migration safety/snapshot → health → atomic switch → restart → smoke. post-switch failure يعيد الإصدار السابق تلقائيًا.

## Disaster recovery
SQLite online backup + SHA-256 manifest + integrity verify + automated restore. migration غير reversible تحتاج verified snapshot. RPO/RTO الافتراضيان ساعة/15 دقيقة وقابلان للضبط.

## Troubleshooting
1. افحص liveness ثم readiness ثم component health.
2. استخدم trace_id لربط structured logs/metrics.
3. DB busy: افحص db_locks وWAL/checkpoint والدisk.
4. queue متوقفة: افحص leases/workers/resource pressure/circuit breakers.
5. Telegram large file: تحقق api_mode/capabilities والمساحة المحلية.
6. model/OpenCode failure: افحص breaker/model catalog/fallback chain.
7. deployment failure: راجع smoke/health ثم current symlink والrollback.
8. migration failure: لا تعاود migration خطرة قبل verify snapshot/report.
