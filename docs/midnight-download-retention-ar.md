# إدارة ذاكرة التنزيلات ووقت تنظيف 00:00 UTC

تحكم المنظومة مدة حفظ ملفات DownloadService لمدة لا تتجاوز 24 ساعة. أضيفت آلية اختيارية لإزالة ملفات اليوم UTC السابق خلال أول 15 دقيقة بعد الساعة 00:00 UTC، مع حفظ ملفات اليوم الجديد.

## الحماية

- لا تنفذ عملية التنظيف إن كانت قاعدة المهام غير متاحة أو يوجد أي job بحالة queued/leased/running/retrying/scheduled.
- لا تنفذ العملية إذا وجدت ملفات نقل جزئي أو دليل عمل .working.
- الملف index.json الموجود إن كان تالفًا يؤدي إلى رفض العملية بدل مسح السجلات.
- يكتب الفهرس الجديد أولاً ثم تحذف الملفات؛ فشل الحفظ لا يحذف الملفات المسجلة. قد تبقى ملفات يتيمة بعد انقطاع الكهرباء وتحتاج عملية إصلاح مدققة يدويًا.
- تستخدم عملية التنظيف حساب مستخدم systemd غير مميز، لا root، ولا تستخدم أوامر شبكة.

## الاختبار

الأمر التالي يعمل ضمن نافذة 00:00–00:14 UTC فقط ويطبع JSON:

```bash
python scripts/expire-midnight-downloads.py
```

يضيف المستودع ملفات systemd التالية: deploy/opencode-bridge-download-cleanup.service وdeploy/opencode-bridge-download-cleanup.timer. ينسخ المثبت الوحدات لكنه لا يقوم بتفعيل المؤقت تلقائيًا.

تُستخدم الآن آلية قفل ملفات مشتركة لعمليات التنزيل والحذف والتنظيف. لا يزال تفعيل المؤقت على الإنتاج مؤجلاً حتى اجتياز تجارب staging على الطابور والتنزيلات المتزامنة.

عند استكمال الاختبارات على staging، يمكن تمكين المؤقت في حساب خدمة ubuntu بالأمر:

```bash
systemctl --user daemon-reload
systemctl --user enable --now opencode-bridge-download-cleanup.timer
```

الإنجاز الحالي: سياسة 24 ساعة وحدّ UTC ووحدات تنفيذ مع اختبارات محلية/CI. التشغيل الفعلي عند 00:00 UTC والتأكد من عدم المساس بملفات المستخدم يحتاج اختبارات staging قبل تفعيل المؤقت على الخادم.
