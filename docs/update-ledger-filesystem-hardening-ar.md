# حماية سجل عمليات التحديث الدائم — T09

أضيف فحص نوع الملفات وملكية وصلاحيات مجلد runtime وسجل SQLite، قبل تسجيل حالة عملية نشر جديدة.

يرفض البرنامج وجود رابط رمزي أو رابط صلب أو ملف جهاز أو FIFO مكان update-operations.sqlite3، ويشمل الفحص ملفَي WAL وSHM اللذين قد ينشئهما SQLite.

يُنشأ سجل SQLite الجديد بوضع صلاحيات خاص ويُضبط الملف الحالي باستخدام واصف ملف لا يتبع الروابط الرمزية في نظام Linux.

عند اكتشاف مجلد يمكن للمجموعة أو مستخدمين آخرين الكتابة فيه، تتوقف العملية ولا تنفّذ نشرًا تلقائيًا؛ يجب أن يراجع المسؤول ملكية runtime قبل تشغيل التحديث.

**مهم:** هذه حماية من أخطاء المسار والتداخل مع مستخدمين آخرين. إذا كان وكيل البرمجة يعمل بنفس حساب Unix الذي يملك runtime، فلا تحمي صلاحيات 0600 من تعديله. لذلك يبقى فصل مستخدم وكيل OpenCode وعزل الشبكة شرطًا ملزمًا في T02.

لا تشكل اختبارات CI بديلاً عن اختبارات النشر والتراجع على خادم staging أو سجل تشغيل إنتاجي.
