# قائمة اختبار إصدار OpenCode Bridge v3.3.0

الإصدار المجمّع من أعمال ما بعد v3.2.0. نتائج GitHub Actions هي فحص للشيفرة ولا تثبت خادم الإنتاج. اختبر في staging إن أمكن، واحتفظ بنسخة احتياطية حديثة قبل تثبيت أي تحديث.

## فحوص ما قبل الترقية

- [ ] تأكد من امتلاك GitHub Release بوسم v3.3.0 ووجود أرشيف tar.gz وملف SHA256SUMS وأن التحقق من البصمات ناجح.
- [ ] تحقق من أن وسم git وملف VERSION يشيران إلى 3.3.0 وأن CI الخاص بالوسم نجح.
- [ ] خذ نسخة مشفرة باستخدام age واحفظ مفتاح فك التشفير خارج الخادم؛ لا ترسله عبر تيليجرام أو GitHub.
- [ ] تحقق من أن جميع العمليات المجدولة انتهت أو يمكن إيقافها بأمان، وأن rollback للإصدار السابق متاح.

## قائمة التجارب

- [ ] إعادة تشغيل خدمة تيليجرام والخادم المحلي؛ جرب /start والقوائم والمهام والتعليقات دون ظهور بيانات سرية.
- [ ] المستخدم المفرد يستطيع إدارة الخادم؛ وإذا كان هناك أكثر من مستخدم، عيّن TELEGRAM_OWNER_ID صراحة ثم اختبر أن الآخرين لا يمكنهم تحديث النظام أو إدارة المفاتيح.
- [ ] تفعيل emergency-stop يوقف تحديثات Bridge وOpenCode وUbuntu اليدوية والتلقائية، ولا يمنع المهام العادية. ألغِه صراحة بعد الاختبار.
- [ ] جرّب وضع notify ومراقبة نتائج فحص التحديث بدون نشر. لا تفعّل auto-safe قبل اجتياز اختبار النشر والتراجع.
- [ ] أنشئ نسخة احتياطية صغيرة، وافحص SHA-256، وجرّب فك التشفير والاستعادة في مجلد staging منفصل.
- [ ] جرّب تنزيل رابط HTTPS عام؛ وتأكد من رفض localhost والعناوين الداخلية ورابط metadata ومنع إعادة توجيه غير آمنة.
- [ ] جرّب عمليتي تنزيل متزامنتين وتأكد من بقاء فهرس الملفات متسقًا وعدم تجاوز الحصة.
- [ ] تحقق من حد حفظ الملفات البالغ 24 ساعة ومن خيارات تنظيف 00:00 UTC. اترك مؤقت systemd الإضافي غير مفعّل حتى نجاح اختبار التزامن.
- [ ] تحقق من صحة قاعدة SQLite والمهام المؤجلة بعد إيقاف/تشغيل الخدمة وتجربة رفض عمليات تحديث متزامنة.
- [ ] اختبر التعافي من فشل مقيّد في staging، وسجّل أوقات RPO/RTO ونتائج اختبار 24–72 ساعة قبل اعتماد التشغيل الآلي الكامل.

## دليل الحالة

لإظهار الجرد الآمن محليًا على المضيف:

```bash
python scripts/host-inventory.py
```

لا تعرض ملفات .env أو الأسرار ولا تلصقها في تقارير عامة. عند الفشل احفظ رقم الإصدار والوقت ورسالة الخطأ المنقّحة فقط. إذا فشلت الاختبارات الأساسية، أوقف التحديثات باستخدام emergency-stop قبل اتخاذ قرار الاستعادة بالإجراء الموثق الخاص بالخادم.

أعمال T01–T18 التي تتطلب staging أو وصولًا لخادم Ubuntu تبقى غير مكتملة حتى يقدم اختبار التشغيل الحقيقي دليلًا عليها.
