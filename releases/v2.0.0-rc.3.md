# OpenCode Bridge v2.0.0-rc.3

نسخة تجريبية للاختبار على الخادم، تضيف لوحة تحكم كاملة بالأزرار فوق مُنتقي الموديلات في `rc.2`.

## لوحة التحكم

أمر `/menu` يفتح لوحة واحدة تجمع كل الوظائف في أقسام، وكل شاشة تعرض حالتها الحقيقية وتتيح التحكم منها:

| الشاشة | المحتوى |
|---|---|
| القائمة الرئيسية | التنقل بين الأقسام |
| الإعدادات | الإعدادات الفعلية غير السرّية + حالة تثبيت النموذج |
| النموذج ومستوى الاستدلال | يفتح مُنتقي الموديلات في نفس الرسالة |
| المهام | المهام الجارية والفاشلة + إعادة محاولة + إلغاء |
| الجدولة | الجداول + تفعيل/إيقاف + حذف |
| حالة النظام | تقرير صحة كامل + الحدود الفعلية |
| الملفات والتنزيلات | شاشة تجريبية؛ التحميل في إصدار مستقل |
| المساعدة | الأوامر مجمّعة حسب الوظيفة |

كل شاشة غير الرئيسية تنتهي بزر «‹ رجوع للقائمة»، وكل إجراء مدمّر يمرّ بزر تأكيد.

## قرارات بنوية

- `bridge/services/**` لا يستورد `telegram`.
- الشاشات لا تعرف `bot.py`؛ تطلب قيمًا مسمّاة من `PanelContext` عبر دوال async.
- `bot.py` هو الربط الوحيد بين الخدمات الحقيقية والشاشات، فتُختبر كل شاشة بحقول callable عادية.
- حفظ تبويب واحد: `build_panels()` هو مكان تسجيل أي شاشة جديدة.

## حدود `callback_data`

الشاشات تتحدث بأسماء قصيرة فقط: `pnl:go:<شاشة>`، `pnl:do:<شاشة>:<إجراء>:<وسائط>`، `pnl:yes:` / `pnl:no:` للتأكيد. الدالة `assert_short()` تُفشل البناء فورًا إذا تجاوز أي زر 64 بايت، والاختبارات تتحقق من ذلك على كل شاشة. لا يوجد أي نص حر داخل الأزرار.

## لا تبديلات وهمية

`UserPreferences` يحتوي ثمانية حقول لا يقرأها أي كود تشغيلي. لذلك تعرض شاشة الإعدادات القيم الفعلية قراءةً، ولا تعرض زر تبديل لخاصية لا أثر لها. ربط هذه الحقول بالـ runtime عمل منفصل قادم.

## الاختبارات

18 اختبار E2E جديد على SQLite حقيقي وخادم HTTP حقيقي: الراوتر الفعلي، المخازن الفعلية، والتحقق من تدفّق التأكيد والإلغاء والحذف على بيانات حقيقية. إجمالي الاختبارات 462.
