# v3.43.0 — A question is not a completion (2026-10-17)

## Finding

`is_task_complete` decided whether a durable multi-day job finishes or defers
to the next UTC noon. The done-phrase fallback matched a phrase *anywhere* in
the last line, so these all finished the job:

- `I am not sure the task is complete`
- `job completed? no`
- `المهمة ليست مكتملة بعد`

The Arabic question mark also survived punctuation stripping, so
`[[BRIDGE_TASK_COMPLETE]]؟` counted as a completion. A false completion closes
the task and tells the owner the work is finished.

## Change

- The line must **be** the done phrase, optionally with a short sign-off
  (24-character budget, documented).
- Any hedged line is not a completion: questions (`?` `؟`), negations
  (`not `, `n't`, `غير`, `لم `, `ليست`, `ليس`) and partial wording
  (`جزئي`, `مؤقت`, `ما زال`).
- The sentinel tail is checked for hedging **before** punctuation is stripped,
  so a trailing question mark cannot be silently normalised away.
- Deliberate bias: a missed completion costs one more day; a false one can
  discard weeks of work.

## Tests

`tests/test_daily_completion.py`: hedge, question, long-tail, sentinel-strength
and continuation-delay cases added; every pre-existing assertion still holds
(verified case by case against the new rules).

## Upgrade

No deps, no migrations. Behaviour change: hedged or questioning final lines no
longer complete a daily task. Source release only.
