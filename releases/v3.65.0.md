# v3.65.0 — Freebuff backend and documentation consolidation (2026-11-11)

## Summary

This release adds an optional **Freebuff CLI** backend for owners who want a
second agent runtime, while keeping **OpenCode as the default** and preserving
the existing Telegram task lifecycle. It also consolidates the project
documentation and restores the CI quality gate after the Dependabot updates.

## Added

- `AgentBackend` contracts, normalized events, user-safe errors and capability
  descriptors under `bridge/domain/agent/`.
- A Freebuff implementation with binary/version/login probing, a stdlib PTY
  runner, bounded ANSI screen handling, a defensive `chat-messages.json`
  reader, answer extraction and `FreebuffBackend`.
- `BackendRouter` with `AGENT_BACKEND=opencode|freebuff|auto`, per-owner
  preferences and `/backend` selection/status.
- Additive `backend_sessions` and `backend_preferences` tables; the legacy
  `sessions` schema is untouched.
- Arabic and English operator guides, an ADR, a simulated-TUI PTY fixture and
  unit/integration coverage under `tests/freebuff/`.

## Changed

- `AgentService` delegates through the backend port; OpenCode still takes the
  legacy client path and remains behaviorally unchanged.
- `TaskExecutionService` consumes backend-scoped events while retaining the
  single editable Telegram status message.
- Cancellation is owner-scoped and terminates the Freebuff process group.
- Documentation now centers on architecture, project status, roadmap, decisions
  and the session log. Obsolete T01–T54 and 2.0 planning pages were removed;
  their history remains in Git.

## Security

- Freebuff is opt-in and disabled by default (`AGENT_BACKEND=opencode`).
- `log.jsonl` is never read, copied, logged or delivered because it may contain
  a plaintext account key after authentication errors.
- Prompt text is staged in a `0600` file rather than passed in `argv`; the CLI
  receives a minimal environment without Telegram or provider secrets.
- The working directory is confined to the configured workspace, and output is
  ANSI-stripped, secret-redacted and length-bounded before delivery.
- Unsupported versions, missing login, unknown TUI states and unreadable chat
  stores fail closed.

## Fixed

- Pre-existing Ruff violations in `scripts/render_telegraph_digest.py`.
- `SC2046` word-splitting warnings in `scripts/render_digest_wrapper.sh`.
- The CI supply-chain pin test after the reviewed `actions/setup-python` update.

- Linux PTY smoke with a deterministic fake TUI: passed.
- Core affected tests: 27 passed.
- Linux CI on the consolidated `main`: Build and Release and Python

- Release assets were published with checksums:
  `opencode-bridge-v3.65.0.tar.gz` and `SHA256SUMS`.
- The local Windows full-suite failures match the pre-change baseline and are
  environment-specific; Linux CI is the release gate.

## Upgrade

- No new Python runtime dependency and no migration step; the new tables are
  additive and created at startup.
- Freebuff is optional: install `freebuff`, run `freebuff login` as the service
  user, configure the workspace, then select it with `/backend freebuff` or
  `AGENT_BACKEND=freebuff`.
- Roll back immediately with `/backend opencode` or
  `AGENT_BACKEND=opencode` and a service restart.

## Known limitation

The PTY path was validated against a deterministic simulated TUI. A real
Freebuff account must still be exercised on a Linux host to confirm vendor-side
login, quota, `--continue`, cancellation and current screen-shape behavior.
