# v3.37.0 — Attachment representations wired (2026-10-17)

## Changes

- `AttachmentContextService`: in-process bounded representations — text
  excerpts (query-relevant chunks, document order) and validated ZIP
  manifests. No new dependency, no subprocess.
- `AttachmentIntelligenceRouter.select_ordered_chunks()` keeps document
  order; `select_text_chunks()` unchanged.
- `TaskExecutionService` inlines the block (untrusted-data label), stops
  uploading represented files as raw parts, audits
  `attachment_context_derived`, and degrades to the previous behaviour on
  any failure.
- `tests/test_attachment_context_service.py`,
  `tests/test_attachment_context_wiring.py`.

## Bounds

≤ 5 files, ≤ 256 KiB read and ≤ 8 000 chars per file, ≤ 24 000 chars per
task, ≤ 200 archive entries.

## Not included

PDF/video/audio processors stay out of the task path: they shell out
synchronously (`subprocess.run`, 120 s timeout) and would block the event
loop. They need an async deadline first.

## Upgrade

No deps, no migrations, no new host tools. Source release only.
