# OpenCode Bridge v1.8.0

## Highlights

- Added persistent named scheduled jobs stored independently from individual executions.
- Added complete Telegram schedule management: create, list, inspect, rename, edit, append, reschedule, change recurrence, run now, pause, resume and delete.
- Added large-command assembly through repeated `/schedappend` operations with restart-safe SQLite storage.
- Removed user-facing task IDs and queue positions from the ordinary task experience.
- Unified queueing, live progress and final text into one continuously edited Telegram status message.

## Persistent Scheduling

Create a one-time schedule:

`/schedule name | YYYY-MM-DD HH:MM | command`

Create a recurring schedule:

`/repeat name | 1d | command`

Manage saved schedules with:

- `/schedules`
- `/schedshow name`
- `/schedrename old | new`
- `/schededit name | new command`
- `/schedappend name | additional command text`
- `/schedtime name | YYYY-MM-DD HH:MM`
- `/schedinterval name | 1d`
- `/schedinterval name | once`
- `/schedrun name`
- `/schedpause name`
- `/schedresume name`
- `/scheddelete name`

Schedules survive process restarts. Manual runs do not consume or delete their definitions. Recurring schedule executions use the normal serialized queue so one owner does not receive overlapping agent executions.

Times are currently entered and displayed in UTC.

## Large Scheduled Commands

The complete scheduled instruction is persisted as SQLite TEXT. Telegram message-size limits can be bypassed safely by building the command in chunks with repeated `/schedappend` calls. Tests cover prompts larger than 60,000 characters and verify restart persistence.

## One-Message Task Lifecycle

Ordinary text, research and instruction-bound attachment tasks now use a single Telegram status message. The bridge edits that message through live progress and replaces it with the final result instead of creating queue-number, progress and result messages separately.

Internal task IDs remain available for audit/storage but are not exposed in the normal Telegram UI.

## Verification

CI covers persistent schedule creation, case-insensitive names, editing, large prompt append, pause/resume, deletion, manual runs, recurrence advancement, one-time execution and schedule error tracking, in addition to the existing media, model, queue and security tests.
