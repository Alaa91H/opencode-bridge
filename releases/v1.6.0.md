# OpenCode Bridge v1.6.0

## Highlights

- Added a persistent two-line free-points header above final Telegram agent responses.
- Added per-command local usage metering that reflects OpenCode assistant/model turns, including tool-call loops and automatic retries.
- Included daily Agent Scout and autonomous maintenance-agent requests in the same persistent free-tier accounting.
- Added immediate local exhaustion detection when OpenCode returns a free-tier limit response.
- Consolidated and removed all non-default repository branches after verifying their work was already integrated into `main`.

## Free-Points Visibility

Every final Telegram response now begins with exactly two accounting lines:

```text
النقاط المجانية المتبقية اليوم (تقديري): 197/200
استهلاك هذا الأمر: 3 نقاط
```

- Usage is persisted in `runtime/free-points.db`, so service restarts do not reset the same-day local counter.
- The counter resets automatically on the next configured local day.
- `OPENCODE_FREE_DAILY_POINTS` controls the local daily ceiling and defaults to `200`.
- OpenCode Zen does not currently expose an authoritative remaining-free-quota value to clients, so the remaining value is explicitly labelled as an estimate instead of presenting an invented upstream balance.

## Usage Metering

- The bridge snapshots OpenCode session messages around each prompt and counts newly created assistant/model turns.
- Commands that trigger multiple internal model turns therefore consume more than one locally tracked point.
- Automatic inference retries are reflected in the command-level usage total.
- A `429`, `FreeUsageLimitError`, or matching free-usage-exceeded response immediately marks the local daily estimate as exhausted.
- The daily autonomous maintenance task and Agent Scout use the same persistent counter rather than a separate hidden budget.

## Repository Consolidation

- Verified that all historical feature branches were either strictly behind `main` or already represented exactly in the `main` tree after squash merges.
- Reconciled the free-points feature branch by tree hash before cleanup, preventing loss of squash-merged work.
- Deleted every non-`main` branch from the GitHub repository.
- Used a one-shot GitHub Actions cleanup workflow with scoped `contents: write` permission, then removed that workflow immediately after successful cleanup.
- The repository now has `main` as its only branch.
