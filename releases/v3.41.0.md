# v3.41.0 — Reboots and restarts join the host guard (2026-10-17)

## Change

- `HostController.reboot`, `restart_service` and `cleanup_now` consult the same
  process-wide `HOST_OPERATIONS` guard as the update path, returning
  `ActionResult(False, "busy", <running label>)`.
- `reboot()` refuses before the sudoers probe, so a refused request executes no
  host command at all.
- `restart_service` still validates the service key first, so an unknown key
  keeps raising exactly as before.
- Panel shows `host_busy` in Arabic and English instead of the generic
  "could not complete, please retry" text, which would have invited a second tap.

## Tests

`tests/test_host_control_guard.py`: reboot/restart/cleanup refused while the
guard is held, no command executed, unknown key still raises, free host runs
normally. No test runs a host command.

## Upgrade

No deps, no migrations. Behaviour change: power, service and cleanup actions are
refused while an update is in flight. Source release only.
