# OpenCode Bridge v1.5.0

## Highlights

- Added production-ready Telegram control for the OpenCode development agent with per-task reasoning-variant forwarding and stronger repository-development instructions.
- Added automatic daily selection of the strongest currently verified zero-cost OpenCode Zen model, using the highest supported reasoning variant exposed by the live catalog.
- Added autonomous daily host maintenance, safe system package updates, cleanup, and a read-only post-maintenance agent audit.
- Added guarded self-update from the trusted `Alaa91H/opencode-bridge` repository with temporary-worktree verification before fast-forward deployment.
- Added boot-persistent ZRAM sized to 50% of physical RAM by default, removing the previous 2 GiB cap.

## Autonomous Model Management

- Agent Scout now re-evaluates zero-cost Zen models every day instead of permanently pinning a single model.
- The bridge reads live model metadata and prefers the strongest recognized reasoning level such as `xhigh`, `max`, or `high` when supported.
- Unsupported reasoning variants retry safely without the variant before model fallback.
- Muse Spark 1.3 Contributor Free remains a safe configured fallback instead of an unconditional permanent selection.

## Daily Maintenance and Self-Update

- Daily maintenance now covers APT index refresh, safe package upgrades, autoremove, package-cache cleanup, temporary-file cleanup, journal retention, and managed attachment cleanup.
- The updater accepts only the trusted GitHub origin and only clean fast-forward updates from `main`.
- Candidate updates are validated in a detached worktree with Python syntax checks, the full unit-test suite, OpenCode JSON validation, and shell syntax checks before deployment.
- systemd assets are synchronized after verified updates and services are restarted only when activation is required.
- Unsafe states such as local modifications or divergent history stop automatic updating instead of discarding local work.

## ZRAM and Resource Reliability

- ZRAM is installed and enabled as a boot-level system service.
- The default ZRAM target is exactly 50% of detected physical RAM with no artificial 2 GiB ceiling.
- `zstd` is preferred when supported, with `lz4` as the next choice.
- ZRAM keeps higher swap priority than the bounded disk-swap fallback.
- Live resize occurs only when the active ZRAM device contains no used swap pages; otherwise resizing is safely deferred until reboot.

## Repository Consolidation

- All existing development branch heads were reconciled to the current `main` state after verifying that previously squash-merged or legacy V3 work was already integrated or superseded by newer production code.
- No stale legacy V3 entrypoint was reintroduced over the current modular `run_v3.py` production path.

## Verification

- CI validates Python syntax, the complete unit-test suite, maintenance shell scripts, both OpenCode configuration files, and semantic version format.
- The release is published automatically only after CI succeeds on `main`.
