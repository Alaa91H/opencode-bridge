# OpenCode Bridge v1.8.1

## Telegram cleanup

- Removed the free-points indicator from final Telegram responses.
- Removed the local free-points SQLite tracker, usage injection, quota-specific audit fields, configuration variables, and maintenance reporting.
- Final task responses now contain only the actual result body, subject to Telegram message-length handling.

## Safer self-update

- Self-update can recover a deployment that is checked out at a detached release commit when local `main` can fast-forward safely to `origin/main`.
- Non-conflicting untracked local files no longer block updates.
- Tracked local modifications, divergent history, and untracked files that would collide with tracked files on `origin/main` still block the update.
- Existing stashes are left untouched.
- Candidate code is still validated in a temporary detached worktree before the production checkout moves.

## Verification

- Python compatibility CI, Code Quality, and Supply Chain Security are required before release publication.
- Added regression coverage that prevents the removed points indicator from returning to production code.
