# OpenCode Bridge v1.7.0

This release turns Telegram media and files into durable, instruction-bound OpenCode tasks.

## What changed

- Send a photo, video, audio item or document with a Caption to execute it immediately with that instruction.
- Send one or more files first and the instruction next; the pending batch is persisted in SQLite and survives bridge restarts.
- Telegram albums are grouped into a single task.
- Use `/discard` to remove pending files before execution.
- Every downloaded file is protected by managed-path validation, size limits and SHA-256 integrity checks.
- Attachment content is treated as untrusted data; embedded file instructions cannot override the user's Telegram command.
- Text/model-visible images use OpenCode file parts, while PDF, audio, video and other binaries are routed through validated local paths and preinstalled server tools when available.
- Per-task scratch files used for inspection/conversion are isolated and removed when execution ends.
- Output delivery remains restricted to the managed per-task output directory.

## New settings

- `TELEGRAM_ATTACHMENT_MAX_COUNT=10`
- `TELEGRAM_ATTACHMENT_MAX_TOTAL_BYTES=52428800`
- `TELEGRAM_ATTACHMENT_PENDING_SECONDS=600`
- `TELEGRAM_MEDIA_GROUP_DEBOUNCE_SECONDS=1.25`

The existing `TELEGRAM_ATTACHMENT_MAX_BYTES` setting continues to control the per-file limit.

## Verification

CI covers attachment integrity, task limits, untrusted-content framing, restart-safe pending batches, duplicate suppression and expiration cleanup in addition to the existing project test suite.
