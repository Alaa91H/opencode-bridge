## OpenCode Bridge v1.4.0

### Highlights

- Added a unified 0–100 host health score across memory headroom, Linux memory PSI, swap occupancy, normalized CPU load, and disk capacity.
- Added explicit `healthy`, `degraded`, `high`, and `critical` health levels plus a score-based shadow worker policy that remains isolated from production admission.
- Added rolling production-versus-shadow evaluation with agreement, mean/max delta, aggressive/conservative bias, and advisory promotion readiness gates.
- Added continuously stable evidence requirements so promotion readiness cannot be reached by a burst of fast samples alone.

### Adaptive Worker Reliability

- Kept production worker admission on the existing threshold policy while exposing the score-based policy strictly as shadow telemetry.
- Added hysteresis to shadow health recovery: worsening applies immediately while recovery advances one level at a time with margin above each boundary.
- Preserved gradual production recovery and the rule that running tasks are never cancelled solely because host pressure increases.
- Fixed production wiring so the stable adaptive controller remains authoritative during V3 bootstrap.

### Observability and Audit

- Added low-noise `adaptive_worker_limit` events only on effective worker-limit changes.
- Added `adaptive_worker_shadow_divergence` events for meaningful production/shadow drift transitions: started, changed, and resolved.
- Added `adaptive_worker_shadow_readiness` events when advisory readiness changes between ready and not ready.
- Extended `/resources` diagnostics with health score, shadow health, shadow worker recommendations, rolling agreement statistics, bias, and stable-evidence duration.

### Restart-Safe Shadow Evidence

- Added bounded persistence for shadow readiness evidence in `runtime/shadow-readiness.json` using atomic replacement and restrictive file permissions.
- Recent valid evidence can survive short service restarts, while service downtime is never counted as additional stable time.
- Stale, malformed, future-dated, oversized, or otherwise invalid persisted state is rejected conservatively and evaluation restarts safely.
- Persistence and audit failures remain observability-only and can never alter production worker admission.

### Verification

- Added deterministic coverage for health-score boundaries, shadow hysteresis, worker telemetry, transition auditing, divergence evaluation, readiness gates, continuous stability, diagnostics, production bootstrap wiring, and restart-safe persistence.
- Verified the complete suite through GitHub Actions, including Python syntax, unit tests, OpenCode configuration, V3 configuration, and semantic-version validation.
- No application build or dependency-heavy verification is performed on the control server; GitHub Actions remains the source of truth.
