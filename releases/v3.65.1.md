# v3.65.1 — Container-safe systemd deployment (2026-11-11)

## Summary

This patch fixes deployment on unprivileged container hosts whose user systemd
manager has an empty effective capability set. The Telegram unit still requests
the complete hardening set, but deployment now probes the host and disables only
the optional directives that cannot start there. OpenCode remains the default
backend and application behavior is otherwise unchanged.

## Fixed

- `systemd.py` probes each optional hardening directive through a transient
  `systemd-run` user service and writes a generated
  `20-hardening-compat.conf` containing `<directive>=no` only for rejected
  directives.
- `NoNewPrivileges=yes` remains enabled. A host that supports every directive
  receives no compatibility file, and a stale fallback is removed.
- `scripts/deploy.sh` regenerates units for the restored release during rollback,
  preventing a failed deployment from leaving a newer unit running against older
  code.
- Added coverage for supported and rejected probe profiles, generated-file
  cleanup, the deployment self-check and rollback ordering.

## Upgrade

- No new Python runtime dependency and no migration step.
- Deploy with `scripts/deploy.sh v3.65.1`. The generated drop-in is written
  automatically; do not create a manual override.
- Rolling back with `scripts/deploy.sh` regenerates the restored release's units
  before restarting.
