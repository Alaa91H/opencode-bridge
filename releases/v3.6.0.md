# v3.6.0 — Resource efficiency + control (2026-10-17)

## Efficiency (verified against Oct-2026 best practices)

- SQLite: WAL + `synchronous=NORMAL` + `busy_timeout` were already in place;
  added bounded `cache_size` (64MB), `temp_store=MEMORY`, 64MB `mmap_size`,
  and WAL `journal_size_limit` for the ~1GB host.
- List queries clamp limits to ≤100 rows; audit log rotates at 10MB.
- Polling-heavy intervals (`task_poll_seconds`, watchdog, model sync) were
  audited and intentionally left unchanged: workers wake on demand via
  `wake_tasks()`, and faster cycles would only add idle DB wakeups.

## Customization

- `TELEGRAM_DROP_PENDING_UPDATES=1` skips the offline backlog on restart
  (default `0` preserves current replay behavior).

## Compatibility

- CI matrix: Python 3.12, 3.13, 3.14. Runtime lock already targeted
  3.12–3.14; development build already ran 3.14 (asyncio +10–20%).

## Dependencies (no change, verified latest)

- `python-telegram-bot==22.8`, `httpx==0.28.1`, `aiosqlite==0.22.1`,
  `ruff==0.17.0`.

## Upgrade

No dependency changes, no new units, defaults preserve prior behavior.
Source release only — host upgrade follows the safe-update path.
