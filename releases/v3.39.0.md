# v3.39.0 — Progress persistence coalesced (2026-10-17)

## Change

- `LiveProgressReporter` batches activity writes behind a 5s window instead
  of committing per agent event on the shared SQLite connection.
- `start`, `finish`, `finalize_text` and the end of the event stream force a
  flush, including on cancellation; each flush carries every coalesced entry.
- In-memory progress stays authoritative, so `/progress` and `/trace` are
  unchanged for live tasks.
- `tests/test_progress_persistence.py`.

## Why

One UPDATE + WAL commit per tool transition, taken under the same lock the
worker uses to claim tasks and heartbeat. Fewer commits, less I/O, less queue
latency on tool-heavy tasks.

## Upgrade

No deps, no migrations. Only a mid-task crash can lose the last few seconds
of live activity from the persisted trail. Source release only.
