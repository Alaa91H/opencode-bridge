# OpenCode Bridge v1.7.1

## Highlights

- Added task-local selection of an image-capable OpenCode Zen model for visual media tasks.
- Kept capability routing restricted to active zero-cost Zen models from live catalog metadata.
- Preserved the configured/general model for ordinary tasks; media capability selection does not permanently switch user sessions.
- Expanded attachment documentation to match current OpenCode model-visible format behavior.

## Capability-Aware Media Routing

Visual tasks now inspect the live OpenCode model catalog before inference. When an attachment is an image, PDF, video, animation or video note, the bridge can temporarily prefer a free Zen model whose metadata explicitly reports `capabilities.input.image=true`.

The selector:

- accepts only live OpenCode Zen candidates with explicit zero pricing;
- requires the requested input capability to be explicitly advertised;
- excludes text-only, unavailable, unpriced and paid models;
- respects the normal preferred/pinned model only when that model actually satisfies the task capability;
- applies the media model to the current task request without changing the global model choice for subsequent text work.

This is especially useful for server-side PDF/video workflows where the agent may convert pages or frames into model-visible images before inspection.

## Attachment Processing Clarification

OpenCode directly exposes UTF-8 text and supported raster images to the model. PDF, audio, video and other binaries are therefore kept on validated local paths and inspected through already-installed server tools when needed.

The bridge continues to:

- isolate intermediate conversion artifacts inside a per-task scratch directory;
- return only managed final outputs to Telegram;
- delete task scratch data and non-recurring incoming files after terminal execution;
- treat attachment contents as untrusted data rather than executable instructions;
- refuse on-demand dependency installation for media parsing.

## Verification

- Added deterministic catalog tests for explicit image-capability filtering.
- Added model-manager tests proving a text-only pinned default can be overridden only for the media task while the configured default remains unchanged.
- CI validates the complete Python suite, OpenCode configuration, shell assets and semantic version on Ubuntu 26.04.
